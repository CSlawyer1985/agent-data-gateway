01 · THE PAIN

程序员的数据很简单，
专业服务者的数据极其复杂。

程序员每天面对的

def parse(x):
    return json.loads(x)
# README.md
{"id": 1, "ok": true}

纯文本、代码、结构清晰——今天的 AI 产品大多为此而生。

VS

律师每天面对的

PDF 扫描件、带批注修订的 docx、财务表、聊天记录、邮件及附件、音视频、工程图纸、压缩包……

Agent 最大的问题不是不会分析，而是无法可靠地知道自己是否已完整读取全部材料。

  • 文件遗漏压缩包未展开、附件未拆出→ 分析建立在残缺事实上
  • OCR 未执行扫描件当成空文件→ “无文字层”被误读为“无内容”
  • 表格读取失败多工作表、合并单元格→ 关键数字缺失无人知晓
  • 静默跳过解析失败无人报告→ 无法区分“读全了”与“读不了”
  • 来源无法回溯没有页码、坐标、单元格→ 引用时找不到原文位置
  • 悄悄降级解析器换成低质量兜底→ 报告看起来正常，实际不可引用

04 · WHAT YOU GET

核心承诺：不假装成功。

完整入账

递归发现 + 压缩包/邮件安全展开，每个文件必有 item 或排除记录。“读全了”是可验证的事实。

失败显性化

读不了的文件进 unresolved_items，带阶段、原因与建议。本地解决不了就显性失败，绝不静默降质。

八维质量 + 五旗标

发现/类型/文本/版面/OCR/附件/元数据/锚定；可检索/可提取/可引用/版面敏感/真伪鉴定——“能检索 ≠ 能引用”。

来源锚点

页码、坐标、表格单元、时间码、字段，元素级定位。adg anchor 把命中回溯到原件位置。

不可信输入安全模型

ZIP bomb、路径穿越、符号链接逃逸、宏、PDF JavaScript、worker 资源耗尽，第一版即内置，拦截显性记录。

本地最优 · 隐私

默认全链路本地处理；产物只含包内相对路径，输出前 scrub 兜底清洗，客户秘密不出本机。

处理谱系 · 三身份

source_id / rendition_id / run_id，每次解析记录工具、退出码与哈希，链式可查。

给 Agent 用

Claude Code、Codex 等编码 Agent 经命令行调用，加 --json 即结构化结果；命中带 quotable 与未读全提示。

06 · QUICK START

三条命令，跑通一个材料包。

zsh — adg

    

    
需要 Python 3.10+。复制命令不含需替换 element_id 的 anchor 示例。包已发布到 PyPI；也可 python3 -m pip install agent-data-gateway。重型 worker（Whisper、PaddleOCR、Docling、MinerU 等）不进一键档，按需 adg setup --worker <名称>。exit code 三态：0 = pass / 1 = 完成但有未读全项 / 2 = fail。
