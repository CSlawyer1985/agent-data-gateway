# ADR 0003：分发形态与目标运行环境

- 状态：Accepted
- 日期：2026-08-23

## 背景

README 写的是「让 Agent 获得可信、完整、可追溯的数据输入」，但没有区分**是哪种 Agent**。
这个区分看起来只是措辞，实际决定整条分发路线。

按「终端用户是不熟悉命令行的律师」推进时，路线会自然滑向：单文件冻结二进制 → `.app` 双击入口
→ macOS 代码签名与公证（Apple Developer 账号 $99/年，否则未签名 `.app` 直接报「已损坏」）
→ 最终还要一个图形界面。每一步都是真实工作量，而且互相锁死。

真实情况是：`adg` 的调用者是**开发机上的编码 Agent**（Claude Code、Codex 这类）。
那个环境自带 Python 和终端，不需要双击，也不会被 pip 日志吓到。
`gateway/cli.py` 的输出纪律本身就是这个结论的旁证——stdout 只打一行摘要、`--json` 出完整
JSON、退出码三态，这是给程序读的接口，不是给人看的界面。

## 决策

1. **目标运行环境是开发机上的编码 Agent**（Claude Code、Codex 这类），其宿主已具备 Python。
   不做 `.app`、双击入口、图形界面，也不购置代码签名与公证。
   终端用户（律师）**不经中间产品层**，直接使用这些 Agent——链条是 `adg → Agent → 人`，
   两跳，没有需要额外照顾的第三形态。

2. **分发形态是 `pip install` / `uv tool install` / `pipx install`**。清单（`worker.json`）
   与 adapter 随 wheel 只读分发，已验证 `workers/`、`models/`、`packs/` 均正确进包，
   且各 worker 的 `.venv` 不会被误打进 wheel。

3. **冻结打包（PyInstaller）否决**，依据是实测而非推断：
   - 能打出 20MB 单文件，`adg --version` 正常，能从内嵌包发现 36 个 worker；
   - 但冻结二进制不是 Python 解释器，**没有 `venv` / `ensurepip`，装不了任何三方包**；
   - onefile 每次运行解包到新的 `_MEI…` 临时目录，**即便装进去，下次运行就没了**。

   这两条直接与「三方依赖不随包分发、装完再按需下载」的既定设计冲突，无法调和。
   曾评估的替代路径（python-build-standalone，约 30MB 可重定位 CPython）能解决装依赖问题，
   但它只在需要面向非技术终端用户时才有意义，已随决策 1 一并搁置。

4. **可写状态与只读分发分离。** worker 的 venv 落在 `ADG_HOME`（默认 `~/.adg`，环境变量可
   覆盖），不落在 `site-packages`。`uv tool` / `pipx` 升级会重建整个环境，装在包内的依赖会
   连带丢失，卸载也不清理，且多个项目各装一份时无法共享。清单旁已存在 `.venv` 时沿用，
   仓库内既有开发环境不受影响。

5. **运行时统一 Python 3.12**，不为用户升级 Python 大版本编写兼容、迁移或自动重建逻辑。
   `pyproject.toml` 的 `requires-python >=3.10` 是包的兼容声明，不是部署约定。
   worker venv 因解释器变更而失效时，`adg check` 本就会探测出不可用并提示重装，以此为兜底。

6. **不提供 Agent 自动发现入口。** 不随包安装 skill、`CLAUDE.md` / `AGENTS.md` 片段，
   也不做 MCP server。由使用者主动让 Agent 调用 `adg`：工具负责在被调用时给出诚实结果，
   不负责让自己被发现。

7. **输出的可理解性由工具自己承担**，与决策 6 不矛盾：决策 6 排除的是「让 Agent 发现 adg」，
   而被调用之后 Agent 能否正确理解输出，是本工具自己的责任——**被误读的诚实结果不是诚实结果**。
   承载点是 `adg --help`（Agent 接触陌生 CLI 的第一动作，命中率高于任何随包文档），
   不新增协议层、不加 `adg protocol` 这类子命令（Agent 不知道要去调，等于没有）。
   三件事必须在那里说清，它们都有实测依据：
   - **退出码三态**，尤其 `1 = 完成但有未读全项，不是失败`。1 是常态（只要有一项没读全就是 1），
     而 Bash 里的非零退出码会被 Agent 默认读成命令失败，可能触发重试、报错或放弃。
   - **典型工作流顺序** `scan → parse → search`。子命令列表看不出依赖关系。
   - **检索范围只覆盖已可靠读取的材料**。这是本项目全部价值的落点。
   同理，`extraction_coverage` 是文件级完整性、不是信息利用率，输出里必须自带消歧说明——
   利用率（[ADR 0002](0002-utilization-as-first-class-goal.md)）上线后两个百分比并列，歧义会翻倍。

## 后果

- 「怎么方便安装」不再是打包问题，而是 `adg setup` 的问题：依赖下载体验、镜像选源、
  失败重试都在 CLI 内解决，不引入构建期复杂度。
- 不承担签名证书、公证流水线、universal2 双架构与 GUI 的长期维护成本。
- 首次安装需要下载数百 MB 依赖，这在目标场景下可接受——调用者是程序，不是等待的人。
- 决策 3 的实证结论不在 git 历史中（相关探索代码未提交），本 ADR 是其唯一记录；
  再次提出冻结打包前应先复核这三条实测事实。
- 决策 4 落地于 `gateway/workers.py` 的 `ADG_HOME` 与 `worker_venv_dir()`，
  `~/.adg/workers` 本就在 worker 发现链上，无需新增发现路径。
- 决策 6 排除了一整类工作（skill 分发、`adg init` 写入项目配置、MCP server），
  它们不再是「尚未做」，而是「不做」。使用方自行配置的成本由使用方承担。
- 决策 7 把「Agent 读得懂」变成 `--help` 的持续维护责任：退出码语义、工作流顺序与
  检索范围警告必须与实际行为同步。这类文本漂移不会让测试变红，却会让 Agent 误判，
  因此需要用测试把它钉住。
