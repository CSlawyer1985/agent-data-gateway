# ADR 0002：资料利用率作为一等目标，降级链之外增加增益轨

- 状态：Accepted（设计决策；实现未开始）
- 日期：2026-08-22

## 背景

项目此前的核心命题是**完整性**：包内每个文件都必须入账，读不了的显性失败
（`all_items_accounted` / `unresolved_items` / `extraction_coverage`）。这个命题已经实现并验证。

真实使用中暴露出第二个问题：**完整性 100% 不等于信息拿全了**。

一份 200 页扫描合同，文字层提取成功 → 完整性记 100%；但里面的公章位置、手写签名、
骑缝章、附件表格全部没有提取。工具报告"读完了"，律师仍然要自己翻原件。
律师的真实诉求是**尽可能提高现有资料的利用率**——同一份材料，用一个工具可能只利用了 60%，
用多个工具从多个角度处理，利用率才能上去。

技术上，当前架构恰恰阻止了这件事：`gateway.dispatcher` 的解析链在第一个 worker 成功后
直接 `return`，链上后续 worker 不再执行。这是 `or` 语义——**它防住的是"锤子坏了没有备用"，
没有防住"世界不只有钉子"**。pypdf 成功之后，rapidocr 永远不会去看那份 PDF 里的印章。

## 决策

1. **利用率（utilization）与完整性（completeness）并列为一等目标**，两者正交、不得互相替代：
   完整性是横向的文件级覆盖，利用率是纵向的文件内信号覆盖。规范见
   [spec 11](../spec/11-utilization.md)。

2. **在降级链之外增加增益轨（enrichment）**。`ROUTE_RULES` 的动作从
   `parse` / `expand` / `unresolved` 扩展为四种，增加 `enrich`：主轨成功后按信号缺口继续触发，
   不再第一个成功就结束。不同 worker 提供的是**不同种类的事实**（文字视角 / 视觉视角 /
   容器视角 / 密码学视角），不是同一事实的不同精度。

3. **利用率的分母必须是探测到的事实，不得是估计**。编排器用 stdlib 做廉价信号探测
   （PDF 对象树、Office XML、文件头），结果三态记录 `present` / `absent` / `unknown`；
   探测不确定必须记 `unknown` 并排除出分母，不得默认 `absent`。这条与「完整入账靠清点而非感觉」同源。

4. **多轨产物不合并**。每条轨产出独立 rendition，各自保留身份与 lineage，检索层做 union。
   合并会破坏 `rendition_id` 的内容哈希语义与 lineage 可追溯性，
   而这两者是 [ADR 0001](0001-contract-authority-and-write-ownership.md) 第 6 条确立的不变量。

5. **多轨读数分歧只记录、不裁决**。分歧本身是高价值输出（一处金额两个 parser 读法不同，
   对律师的价值可能高于其他 99 条读对的内容），但摄取层不得自动选出"正确"读数——
   与「摄取 ≠ 取证」同源：系统提供线索，判断权归人。

6. **成本控制靠机制，档位只是界面**。降本的实体是：探测门控、页级/区域级增益、身份缓存、
   条件升级、预算调度。在其之上提供 `--profile fast|balanced|quality` 供用户选择投入。

7. **快速档也必须报告利用率缺口**。"快速"的含义是"我知道还有什么没提取，但你让我先跑快的"，
   不是"我假装提完了"。任何档位下静默跳过增益任务都等同于假装成功，是被禁止的。

## 后果

- `extraction_coverage` 不再是包质量的唯一指标；报告与 `adg status` 需要同时呈现完整性与利用率，
  二者语义必须在输出中清晰区分，避免读者把 100% 完整性误读为信息拿全了。
- Dispatcher 从"选出一个赢家"变成"跑完一组视角"，`--force`、resume、缓存键与并发预算都要按
  `(source_id, worker, version, config_hash)` 重新界定。
- manifest item 增加 `signals` 字段；Schema 属于破坏性扩展，按 ADR 0001 第 5 条走新版本与迁移。
- 探测器成为新的正确性风险点：探测虚低会让利用率虚高。验证矩阵必须以手工清点的 fixture 固定分母。
- 增益轨会显著增加运行成本与分歧数量，二者都需要分级与预算，否则工具从"帮你读全"变成"把你淹没"。
- 本 ADR 只确立方向与不变量，不锁定信号清单的具体条目与权重——那些随实现修订，以 spec 11 为准。
